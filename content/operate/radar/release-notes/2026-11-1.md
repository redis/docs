Redis Radar 2026.11.1 shows high-availability status in the **Databases** list and agent health in **Settings > Agents**. It lets local users change and reset their passwords, lets the API server serve HTTPS, and fixes gaps in agent and Redis Cloud collection.

This is a Short-Term Support (STS) release. See [Self-managed releases](/content/operate/radar/release-notes/_index.md#self-managed-releases) for more details.

## Enhancements

- **High-availability status.** The **Databases** list now shows the high-availability status of each Redis Software database, and a **High availability** summary card counts the databases without it.
- **Agent health.** **Settings > Agents** now shows warnings for each agent and the collection status of each of its sources.
- **Change your password.** Local users can change their own password from **Change password** in the user menu. Changing it signs you out of your other sessions. See [Change or reset a local password](/content/operate/radar/manage-access.md#change-or-reset-a-local-password).
- **Reset a local user's password.** Operators with access to the Radar host or cluster can reset a local user's password with `radar user reset-password --user <username-or-email>`. The command prompts for the new password, or reads it from standard input with `--password-stdin`. It also clears a lockout and ends the user's sessions. See [Change or reset a local password](/content/operate/radar/manage-access.md#change-or-reset-a-local-password).
- **HTTPS on the API server.** The API server can now serve HTTPS itself, so traffic stays encrypted up to the process. It's off by default.
  - **Helm**: set `app.tls.enabled` to `true` and `app.tls.existingSecret` to a `kubernetes.io/tls` Secret in the release namespace. If an Ingress is in front of Radar, set `ingress.backendTLS` to your Ingress controller. You can't combine this with the OpenShift Route. See [Install on Kubernetes with Helm](/content/operate/radar/install.md#install-on-kubernetes-with-helm).
  - **RPM**: set `HTTP_TLS_CERT_FILE` and `HTTP_TLS_KEY_FILE`. See [Install on RHEL with the RPM](/content/operate/radar/install.md#install-on-rhel-with-the-rpm).

  Restart the API server after you rotate the certificate.
- **LDAP sign-in failures.** **Settings > Security** now lists recent LDAP sign-in failures.
- **Packaged documentation.** Updated the documentation packaged with the Helm chart and the RPM.
- **Dependencies.** Updated Go to fix GO-2026-6809, and updated other dependencies.

## Resolved issues

- **Edited managed-agent sources.** A managed agent no longer stops collecting after you edit one of its sources. If you edited a source before you upgrade, save it again.
- **Managed agents with no sources.** A managed agent with no sources no longer fails its heartbeat.
- **Agent source failures.** A failed source no longer marks the other sources of its agent as failed.
- **Interrupted collections.** Redis Open Source and Redis Cloud connections no longer stop collecting when a worker stops during a collection.
- **Redis Cloud collection timeouts.** Redis Cloud collections no longer fail after 1 minute.
- **Removed cluster resources.** Nodes, shards, alerts, and database health no longer stay in Radar after a Redis Software cluster stops reporting them.
- **Active-Active summary through an agent.** Redis Software clusters connected through an agent now show their Active-Active summary.
- **Redis Open Source through an agent.** Redis Open Source sources connected through an agent now show their connection and databases.
- **Redis Cloud endpoints.** Radar now collects from a Redis Open Source connection that points to a Redis Cloud database endpoint.

## Breaking changes

- **Audit retention limit.** `AUDIT_RETENTION_DAYS` now accepts at most `36500`. If the value is larger, Radar doesn't start. Change it before you upgrade.
- **HTTPS backend-protocol annotations.** Helm now rejects an Ingress or Service annotation that sets an HTTPS backend protocol while `app.tls.enabled` is `false`. Remove the annotation before you upgrade, or enable HTTPS on the API server.
