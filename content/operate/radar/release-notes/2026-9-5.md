Radar can now collect from clusters it can't reach directly. You install an agent on a host inside the network that holds them, and the agent opens an outbound connection to Radar.

This is a Short-Term Support (STS) release. See [Self-managed releases]({{< relref "/operate/radar/release-notes" >}}#self-managed-releases) for more details.

## Enhancements

- **Connect clusters with an agent.** Collect from **Redis Software** and **Redis Open Source** clusters behind a firewall, in a private subnet, or on a segmented network. Radar needs no inbound access to your network. Radar accepts agent connections on its agent gRPC endpoint, which isn't enabled on every Radar deployment. See [Connect clusters with an agent]({{< relref "/operate/radar/agent" >}}).
- **Managed and static agents.** Choose between two modes. **Managed** agents receive source credentials from Radar, so you add and change sources from the Radar UI. **Static** agents read their sources from a file on the agent host, so those credentials never leave it.
- **Isolated networks.** Collect from a fully isolated network by exporting to a file on one host and submitting it from another.
- **Agent packages.** Install from standalone agent packages for Linux on amd64, including Federal Information Processing Standards (FIPS) 140-3 builds.
- **Agent tracking.** Track every agent under **Settings > Agents** and in the **Connected agents** list on the Connections page, with its mode, platform, version, and last heartbeat.
