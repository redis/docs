Redis Radar 2026.10.1 adds readable alert descriptions and a complete usage export. It also makes installing from a private registry or on an air-gapped OpenShift cluster simpler, and fixes stale indicators and gaps in Redis Cloud discovery.

This is a Short-Term Support (STS) release. See [Self-managed releases]({{< relref "/operate/radar/release-notes" >}}#self-managed-releases) for more details.

## Before you upgrade

On OpenShift, the chart now accepts only `edge` termination for the Route. If your values set `route.tls.termination` to `reencrypt` or `passthrough`, or set `route.tls.destinationCACertificate`, update them before you upgrade. Helm rejects those values.

## New features

### Alerts and usage

- **Alert descriptions.** Redis Software alerts now include a readable description and, where the cluster reports one, the measured value.
- **Complete usage export.** The **Usage** CSV export now includes the retained raw usage fields and nested data. The export redacts sensitive data and protects against spreadsheet formulas.

### Managed agents

- **Managed-agent audit records.** Radar now records audit events for managed-agent activation decisions, source changes, assignment updates, and failed administrative requests.

### Helm configuration

- **One registry setting for every image.** `global.imageRegistry` now applies to every image the chart pulls: the API server, worker, migration job, `busybox`, and the bundled PostgreSQL container. The `busybox` image also gets its own override, `dbWaitInitContainer.image.registry`, and the `helm test` pod now receives `global.imagePullSecrets`.
- **Polling interval for Redis Software 7.2 and 7.4.** `app.pollerIntervals.compat` sets how often Radar collects from Redis Software 7.2 and 7.4 clusters. The default is `5m`. A shorter interval keeps data fresher but adds load to each cluster's management plane.

### Air-gapped OpenShift

- **Air-gapped values file.** The chart now includes `values-airgap.yaml`, which lists the images to mirror and the values to set for your registry. On OpenShift, pass it after `values-openshift.yaml`.
- **Route certificates from a Secret.** Set `route.tls.externalCertificate.name` to a `kubernetes.io/tls` Secret in the release namespace, so the private key stays out of your Helm values. The chart grants the OpenShift router read access to that Secret unless you set `route.grantRouterSecretAccess: false`. This requires OpenShift 4.16 or later. It's generally available on 4.19 and later, and a Technology Preview on 4.16 through 4.18.

## Bug fixes

- **Freshness reporting.** Cluster and Overview freshness now follows each source's collection interval, so fewer clusters show as stale when they aren't. Amazon ElastiCache freshness metrics stay consistent across worker replicas.
- **Redis Cloud discovery.** Fixed a pagination issue that could make a Redis Cloud Pro subscription with databases appear empty.
- **Collection reliability.** Radar retries a Redis Cloud API read once when it fails with a transient error. A slow Redis Software alert request no longer interrupts health collection.
- **Interface and observability.** The Redis Cloud connection fields are now labeled **API account key** and **API user key**. The nonfunctional Telemetry settings are removed. Agent gRPC observability outcomes are corrected.
- **OpenShift validation.** Helm now rejects Route TLS configurations that can't reach Radar. See [Before you upgrade](#before-you-upgrade).
- **PostgreSQL diagnostics.** When schema migration fails because the database login can't `SET ROLE`, the migration log now includes a hint naming the setting to apply.

## Performance

- **Database queries.** Radar skips health reads that Active-Active details don't need.

## Documentation

- The documentation packaged with the Helm chart and the RPM has improved image-mirroring and external PostgreSQL setup guidance.

## Maintenance

- Updated backend, frontend, and build dependencies.

## Downloads

- **Helm chart**: `radar` version `2026.10.1`, from the Redis Helm repository at `https://helm.redis.io/radar`

### Container images

The Helm chart pulls these images from Docker Hub. For an [air-gapped install]({{< relref "/operate/radar/install" >}}#install-on-an-air-gapped-host), mirror each one to a registry your cluster can reach.

- **API server**: `redislabs/radar:app-v2026.10.1`
- **Worker**: `redislabs/radar:worker-v2026.10.1`
- **Migration job**: `redislabs/radar:migrate-v2026.10.1`
- **Database wait and Helm test**: `library/busybox:1.37`
- **Bundled PostgreSQL**, only if you enable it: `library/postgres:18.4-bookworm`

The Radar images are built for `linux/amd64` only.
