Redis Software for Kubernetes 8.2.6-21 is a feature release that supports [Redis Software 8.2.6](/content/operate/rs/release-notes/rs-8-2-releases/_index.md) and includes new features, bug fixes, and enhancements.

## Highlights

- Support for exposing cluster endpoints and Active-Active databases through the Kubernetes Gateway API.
- Certificate-based authentication for the Redis Software REST API, with the option to turn off basic authentication.
- Support for Redis Software 8.2.6.

## Enhancements

- Added support for exposing the cluster's REST API, Cluster Manager UI, and metrics endpoints, and Active-Active databases, through the [Kubernetes Gateway API](/content/operate/kubernetes/networking/gateway-api.md) <!--RED-112546-->
- Added [certificate-based authentication](/content/operate/kubernetes/security/authentication/certificate-auth.md) to the REST API for the operator and for users, and the option to turn off basic authentication <!--RED-193891-->
- Added REC support for client maintenance notifications, for databases that use the OSS Cluster API and for databases in proxy mode <!--RED-216144-->
- Added [FIPS 140-3](/content/operate/kubernetes/security/fips.md) support on Amazon EKS with Bottlerocket FIPS worker nodes <!--RED-212064-->
- Added the `disconnectClientsOnPasswordRemoval` setting to the REC, REDB, and REAADB, which controls whether the proxy disconnects clients whose password was removed <!--RED-197499-->
- Added Redis Software 8.2.6 support

## Resolved issues

- Fixed the operator overwriting `nodeAffinity` and `podAffinity` set in `redisEnterpriseAdditionalPodSpecAttributes` <!--RED-214283-->
- Fixed the REC getting stuck in the Upgrade state after you upgraded a FIPS-enabled cluster <!--RED-212773-->

## API changes

This release adds fields for Gateway API exposure, REST API authentication, client maintenance notifications, and client certificate validation. The table below summarizes the notable changes. For the complete field-level reference, see the [API reference](/content/operate/kubernetes/reference/api/_index.md).

| **CRD** | **Field** | **Change** | **Description** |
|---|---|---|---|
| REC | `spec.gateway` | Added | Exposes the cluster's REST API, Cluster Manager UI, and metrics endpoints, and Active-Active databases, through the Kubernetes Gateway API. |
| REC | `status.gateway` | Added | Reports the status of Gateway API exposure. |
| REC | `spec.apiCertificateBasedAuth` | Added | Configures certificate-based authentication for the REST API, including the trusted CA and authorized certificate subjects. |
| REC | `spec.operatorClientAuth` | Added | Selects whether the operator authenticates to the REST API with a username and password (`Basic`) or a client certificate (`Certificate`). |
| REC | `spec.apiBasicAuth` | Added | Turns basic (username and password) authentication for the REST API on or off. |
| REC | `status.apiCertificateBasedAuthActive`, `status.operatorClientCertStatus` | Added | Report whether certificate-based authentication is active and the state of the operator's client certificate. |
| REC | `spec.clientMaintenanceNotifications` | Added | Enables client maintenance notifications for databases that use the OSS Cluster API (`ossMode`) and for databases in proxy mode (`proxyMode`). |
| REC | `spec.disconnectClientsOnPasswordRemoval` | Added | Controls whether the proxy disconnects clients whose password was removed, cluster-wide. |
| REC | `status.initContainerFailures` | Added | Lists operator-managed init containers that are failing, one entry per pod and container. |
| REDB | `spec.disconnectClientsOnPasswordRemoval` | Added | Per-database setting for disconnecting clients whose password was removed. Takes effect only when the cluster-level setting is `Auto`. |
| REDB | `spec.clientCertSubjectValidationType`, `spec.authorizedSubjects` | Added | Validate client certificate subjects during mutual TLS authentication. |
| REDB | `spec.replicaReadOnly` | Added | Makes a Replica Of database read-only, for an Active-Passive setup. Configurable only when you create the database. |
| REAADB | `spec.globalConfigurations.disconnectClientsOnPasswordRemoval` | Added | Per-database setting for disconnecting clients whose password was removed. |
| REAADB | `spec.globalConfigurations.clientCertSubjectValidationType`, `spec.globalConfigurations.authorizedSubjects` | Added | Validate client certificate subjects during mutual TLS authentication. |
| REAADB | `status.participatingClusters[].replicationEndpoint` | Added | Reports the replication endpoint each participating cluster advertises. |
| RERC | `spec.replicationPort` | Added | External port for Active-Active replication when databases are exposed through the Gateway API. One port serves all Active-Active databases in the remote cluster. |

## Known limitations

- **Active-Active database updates can be rejected after upgrading to 8.2.6.** On clusters running versions earlier than 8.2.6, a cluster master failover (for example, during a Kubernetes operator upgrade) can interrupt a change to an Active-Active database while the change is in progress. After the upgrade to 8.2.6, updates to that database can still be rejected with 409 – Another operation is already in progress. This only happens if the configuration change started within seconds of the failover. Workaround: Before you upgrade, wait until all pending Active-Active database changes have finished. <!--RED-101603-->

- **SSO configuration does not work with IPv6 or dual-stack (IPv4/IPv6) clusters.** <!--RED-180550-->

- **Upgrades from versions earlier than 7.4.2-2 are not supported.** If you use an earlier version, upgrade to 7.4.2-2 before upgrading to this version.

- **Missing endpoint for admission endpoint (rare).** Restart the operator pod. <!--RED-119469-->

- **The REDB `redisVersion` field cannot be used for memcached databases.** <!--RED-119152-->

- **Modifying the database suffix for an Active-Active database while the services rigger is terminating causes a loop.** The services rigger deletes and recreates ingress or route resources repeatedly. Wait for the services rigger pod to finish terminating before modifying the suffix. <!--RED-107687-->

- **REAADB changes might fail with "gateway timeout" errors, especially on OpenShift.** Retry the operation. <!--RED-103048-->

- **Creating two databases with the same name in the Redis Enterprise Cluster Manager UI deletes the service and makes the database unavailable.** Avoid duplicate database names. The admission controller prevents duplicate names when you create databases through the Kubernetes operator. <!--RED-99997-->

- **Installing the operator bundle produces the warning `Warning: would violate PodSecurity "restricted: v1.24"`.** Ignore this warning. Red Hat documentation identifies this issue as benign. <!--RED-97381-->

- **RERC resources must have a unique name.** The `rec-name/rec-namespace` string must differ from all other participating clusters in the Active-Active database. <!--RED-96302-->

- **Admission does not block REAADB resources with a `shardCount` that exceeds the license quota.** Correct the REAADB configuration and reapply. <!--RED-96301-->

- **The Active-Active controller supports only global database options.** Location-specific configuration is not supported. <!--RED-86490-->

- **Removing an Active-Active setup might leave services or routes undeleted.** Delete the services or routes manually. <!--RED-77752-->

- **Setting `autoUpgrade` to `true` can cause unexpected database upgrades when `redisUpgradePolicy` is also `true`.** Contact support if your deployment is affected. <!--RED-72351-->

- **Using the previous quick start guide causes REDB creation issues due to an unrecognized memory field name.** Use the current version of the Deploy Redis Enterprise Software for Kubernetes guide. <!--RED-69515-->

- **PVC size does not work with decimal values.** Use integer values for the PVC size. <!--RED-62132-->

- **REC might report error states on initial startup.** No workaround exists. Ignore the errors. <!--RED-61707-->

- **HashiCorp Vault integration does not support Gesher.** No workaround exists. Gesher support is deprecated. <!--RED-55080-->

- **REC clusters fail to start on Kubernetes clusters with unsynchronized clocks.** Use NTP to synchronize the underlying Kubernetes nodes. <!--RED-47254-->

- **Deleting an OpenShift project with a deployed REC might hang.** When an REC cluster is deployed in a project (namespace) with REDB resources, you must delete the REDB resources before deleting the REC. The project deletion hangs until you delete the REDB resources. Delete the REDB resources first, then delete the REC, and then delete the project. <!--RED-47192-->

- **Clusters must be named "rec" in OLM-based deployments.** When you deploy the operator through OLM, the security context constraints (SCC) are bound to a specific service account name ("rec"). The deployment fails if the cluster has a different name. <!--RED-39825-->

- **Readiness probe does not correctly report failures.** The StatefulSet readiness probe does not mark a node as "not ready" when running `rladmin status` on node failure. <!--RED-39300-->

- **Internal DNS and Kubernetes DNS might conflict.** DNS conflicts can occur between the cluster `mdns_server` and Kubernetes DNS. This affects only DNS resolution from within cluster nodes for Kubernetes DNS names. <!--RED-37462-->

- **Kubernetes-based 5.4.10 clusters might negatively affect existing 5.4.6 clusters.** Upgrade your clusters to the latest version. <!--RED-37233-->

- **Node CPU usage is reported instead of pod CPU usage.** The reported CPU usage is for the Kubernetes worker node hosting the REC pod, not the pod itself. <!--RED-36884-->

- **An unreachable cluster shows status as running.** When a cluster is unreachable, the status remains `running` instead of showing an error. <!--RED-32805-->

- **Long cluster names cause routes to be rejected.** A cluster name longer than 20 characters causes route rejection because the host part of the domain name exceeds 63 characters. Limit the cluster name to 20 characters or fewer. <!--RED-25871-->

- **Cluster CR (REC) errors are not reported after invalid updates.** A cluster CR specification error is not reported if you update two or more invalid CR resources in sequence. <!--RED-25542-->
