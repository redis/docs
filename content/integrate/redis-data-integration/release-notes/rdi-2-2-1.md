## What's New in 2.2.1

### Breaking Changes

- **New pipeline names have a maximum of 20 characters**: The limit is reduced from 22 characters. Update provisioning scripts that create pipelines with longer names. Updating an existing pipeline does not revalidate its name.
- **Collector resource names change for pipelines other than `default`**: Update scripts, monitoring, and custom ingress rules that refer to collector Kubernetes resources by name. The following name segments change; the pipeline prefix and source name remain part of the resource name. Resource names for the `default` pipeline stay the same.

| Collector | Previous name segment | New name segment |
| :-- | :-- | :-- |
| Debezium | `collector` | `col` |
| Flink | `flink-col` | `fcol` |
| RIOTX | `riotx-collector` | `rcol` |

For example, `orders--collector-mysql` becomes `orders--col-mysql`.

### Bug Fixes

- **Use the Snowflake source's referenced secret provider**: With multiple Amazon Web Services (AWS) secret providers, the RIOTX collector now reads credentials and private keys from the provider referenced by its source instead of the first one.
- **Wait for stopped components to shut down**: Stopping a pipeline or a source no longer reports completion while its pods are still terminating, unless passing `--wait=false`.
- **Support ingress path rewriting for named pipelines**: Ingress annotations now substitute `$SERVICE` in annotation keys and `$PATH_PREFIX` in annotation values with the backend service name and effective path prefix. This lets an AWS Application Load Balancer strip the pipeline prefix when routing requests. The substitutions are available for the Debezium collector, Flink collector, Flink processor, and classic processor metrics exporter.
